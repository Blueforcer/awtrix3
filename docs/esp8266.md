# ESP8266 build (experimental)

AWTRIX 3 was written for the ESP32. The `esp8266` build environment runs it on an ESP8266, such as the Wemos D1 mini from an original AWTRIX 2 or a NodeMCU board. The ESP8266 has about a quarter of the ESP32's RAM, so this build leaves some features out (see [Features not included](esp8266.md#features-not-included)).

!> This build is experimental and community-made. There is no prebuilt firmware and no online flasher for it: you build it from source with PlatformIO. If you can, use an ESP32 instead (see [Upgrade](upgrade.md)).

## Supported boards

Any ESP8266 board with an ESP-12 module and **4 MB of flash**, for example:

- Wemos / LOLIN D1 mini (the AWTRIX 2 controller)
- NodeMCU v2 / v3

Boards with less than 4 MB of flash (ESP-01, some cheap clones) are not supported. The upload log prints `Detected flash size`, which tells you what your board has.

## Pinout

The build uses the AWTRIX 2 pinout, the same as the `awtrix2_upgrade` firmware. D1 mini and NodeMCU boards use the same `D` labels for the same pins, so you can wire either one by this table.

| Board pin | GPIO | Usage or part |
|---|---|---|
| D2 | GPIO4 | Matrix data (can be changed, see [Matrix data pin](esp8266.md#matrix-data-pin)) |
| D0 | GPIO16 | Left button (optional) |
| D4 | GPIO2 | Middle button (optional) |
| D8 | GPIO15 | Right button (optional) |
| A0 | ADC | LDR light sensor (optional) |
| D3 | GPIO0 | I2C SDA, temperature and humidity sensor (optional) |
| D1 | GPIO5 | I2C SCL, temperature and humidity sensor (optional) |

Supported sensors: BME280, BMP280, HTU21DF, SHT31.

Wiring notes:

- **Buttons:** wire each button between its pin and GND.
- **Boot pins:** D3 and D4 must be high and D8 low when the board powers on. Don't hold the middle or right button while powering on, and keep pull-up resistors on the I2C lines.
- **Power:** give the matrix its own 5 V supply and connect its ground to the board's ground. Don't power 256 LEDs through the board's USB or VIN pin.
- **Data signal:** the ESP8266 sends a 3.3 V signal to 5 V LEDs. This usually works. If you see flicker or wrong colors, add a level shifter or a ~330 Ω resistor in series on the data line.

## Building and flashing

You need [PlatformIO](https://platformio.org/). Either install the "PlatformIO IDE" extension in VS Code, or install the command-line tool with Python:

```bash
python -m pip install --user platformio
```

Then, from the repository folder:

1. Build the firmware:

    ```bash
    python -m platformio run -e esp8266
    ```

2. Connect the board over USB and upload the firmware:

    ```bash
    python -m platformio run -e esp8266 -t upload
    ```

    If Windows shows no COM port for the board, install the driver for its USB chip (CH340 or CP2102). To pick a port yourself, add `--upload-port COM5`.

3. Open the serial monitor if you want to watch it boot (optional):

    ```bash
    python -m platformio device monitor -b 115200
    ```

After the first upload you don't need USB any more. To update, open `http://[IP]/update` in a browser and upload `.pio/build/esp8266/firmware.bin`.

The file system doesn't need a separate upload. The firmware creates its folders on first boot.

## Matrix data pin

The matrix data line is on GPIO4 (D2) by default. To use another pin, set its **GPIO number** (not the D label) as `matrix_pin` in `dev.json` and restart:

```json
{
  "matrix_pin": 2
}
```

You can choose GPIO 2, 3, 4, 5, 12, 13, 14 or 15. Any other value falls back to GPIO4.

| GPIO | Board label | Note |
|---|---|---|
| 2 | D4 | Middle button is switched off |
| 3 | RX | Serial input no longer works |
| 4 | D2 | Default |
| 5 | D1 | I2C, so the temperature sensor is switched off |
| 12 | D6 | |
| 13 | D7 | |
| 14 | D5 | |
| 15 | D8 | Right button is switched off. Must be low at boot. |

If the matrix uses a button's pin or one of the I2C pins, that button or the temperature sensor is switched off, because it would read the LED signal.

To change the default instead, build with `-D MATRIX_PIN=<gpio>`, for example by adding it to `build_flags` in the `esp8266` environment.

## Coming from WLED

An ESP8266 with 4 MB of flash that runs WLED can usually be switched to AWTRIX through WLED's own web update page, without USB:

1. In WLED, open Config → LED Preferences and note the GPIO of the LED output.
2. Open Config → Security & Updates, make sure updates aren't locked, then upload `.pio/build/esp8266/firmware.bin` under Manual OTA Update. If WLED refuses the file because it isn't a WLED build, tick the option that skips this check (newer WLED versions have one).
3. After the restart, WLED's files and settings are gone: AWTRIX formats the file system it finds. Connect to the `awtrix_XXXXXX` access point and enter your WiFi details (see [First setup](esp8266.md#first-setup)).
4. If WLED's LED output was not GPIO4, the matrix stays dark until you set `matrix_pin` to that GPIO in `dev.json` (file manager in the web interface) and restart.

To go back, upload a WLED ESP8266 `.bin` at `http://[IP]/update`. If the board doesn't start after any of this, you can always flash it over USB.

## 16x16 panel

There are two ways to drive a 16x16 WS2812B panel. In both, connect its data input to D2 (or set `matrix_pin`) and describe its wiring with `matrix_start`, `matrix_wiring` and `matrix_zigzag` in `dev.json`, see [16x16 panel](hardware.md#16x16-panel).

- **Split layout** (`esp8266` build, matrix layout `3`): the normal 32x8 screen, shown as two halves on top of each other. Every feature works, but text reads like one line wrapped onto two.
- **Native 16x16 build** (`esp8266_16x16`): the apps are laid out for the square panel.

### Native 16x16 build

Build and upload it like the normal ESP8266 build, with the `esp8266_16x16` environment:

```bash
python -m platformio run -e esp8266_16x16 -t upload
```

What it shows:

| | Layout |
|---|---|
| Time | Hours on the top half, minutes on the bottom half, the weekday bar on the last row (`WD` setting). 12 or 24 hours follow your time format; the other time modes don't apply. |
| Date | Day of the month on top, short month name below. |
| Temperature, humidity | Icon on top, value below. |
| Custom apps, notifications | The icon centred on the top half and the text on the bottom half; text that doesn't fit scrolls there. Without an icon the text is centred vertically. A progress bar uses the last row. |
| Live view (`/screen`, `/fullscreen`) | 16x16. |

Not available on the native 16x16 build:

- **Effects and overlays** (background effects, the `effect` and `overlay` of apps and notifications): they are drawn for 32x8.
- **Bar and line charts** in custom apps and notifications.
- **Push icon** (`pushIcon`): icon and text are on different rows.
- **The on-device menu** is not adapted: its texts are too wide for 16 columns.
- **Fullscreen 32x8 GIFs and draw instructions** made for 32x8 are cut off. Draw instructions use the 16x16 canvas.
- **The AWTRIX app's live view** still expects 32x8.

The `matrix` setting (layout) is ignored: the panel wiring always comes from `matrix_start`, `matrix_wiring` and `matrix_zigzag`.

## First setup

1. Connect to the `awtrix_XXXXXX` access point with the password `12345678`.
2. Open <http://192.168.4.1>, enter your WiFi name and password and press connect.
3. The page says that AWTRIX restarts, but shows no IP address yet: on the ESP8266 the WiFi details are only saved there, and the board joins your network after the restart. Its new IP scrolls across the matrix, or look it up in your router.

The ESP8266 doesn't have enough memory to join your network while the access point is running, which is why it restarts first. It waits up to 30 seconds for your network at boot (its first attempt often fails after about 14 seconds, the second one then joins). If it can't reach your network, it opens the access point again and retries every 5 minutes while nobody is connected to it.

Tips:

- **Phones:** many Android phones (Samsung in particular) send browser traffic over mobile data while the access point has no internet, so the page doesn't load in Chrome. Use the "Sign in to Wi-Fi network" screen the phone offers, turn mobile data off, or use a laptop.
- During boot the display shows a static `AWTRIX` text instead of the animation.

## Features not included

These features are not available on the ESP8266:

| Feature | What happens instead |
|---|---|
| Sound: buzzer, DFPlayer, RTTTL and melodies | Sound commands do nothing (`/api/sound` returns 404). The SOUND and VOLUME menu entries are hidden. |
| Online update (`/api/doupdate`, UPDATE menu entry) | Not possible: HTTPS needs more RAM than the ESP8266 has. Update through `http://[IP]/update` instead. The UPDATE menu entry is hidden. |
| Deep sleep (`/api/sleep`) | The matrix turns off, but the board doesn't sleep. Waking up would need D0 wired to RST, and D0 is the left button. |
| Games | Not included. |
| Art-Net | Not included. |
| Battery level | AWTRIX 2 hardware has no battery. |
| Inline base64 JPG icons | Ignored. Icons stored as files in `/ICONS` (JPG and GIF) still work. |
| Serial debug log | Turned off to save RAM. |
| mDNS (`awtrix_XXXXXX.local`) | Turned off: it ran the board out of memory on busy networks. Open the web interface by IP address. The AWTRIX app still finds the clock (UDP discovery). |

Everything else works: native apps, custom apps, notifications, indicators, transitions, effects and overlays, animated icons, the web interface and file manager, MQTT with Home Assistant discovery, the light sensor with auto brightness, and the HTTP API.

## Limits

- **Payload size:** MQTT messages and custom app or draw payloads are limited to 4 KB (8 KB on ESP32).
- **Memory:** about 9 KB of RAM is free while running on your network (measured on a NodeMCU, no MQTT). An MQTT connection takes 4 KB of that. Many large custom apps at once, or large payloads while the web interface is open, can run the board out of memory.
- **Settings:** the ESP8266 has no separate settings storage, so settings are saved in the file system. Formatting the file system resets the settings too.
